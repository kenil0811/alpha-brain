# Review of pull request #3, "Desktop UI on main's core" (3 October 2026, evening)

`kenil0811/alpha-brain#3`, by Vikas (badami-vikas), from the fork's `feat/ui-only`, cut from
PR #1 ("Bridge parity", 70 commits, +25,209). 12 commits, 122 files, +13,788 −2,052, all under
`desktop/` plus two documents under `docs/development/`. Opened 2 Oct 21:51 from main at
`1d4d43b`; main has moved 19 commits since and the PR is not mergeable (seven conflicting files).

**How it was checked.** The branch in a worktree; its own checks run there (typecheck clean;
14 files, 58 tests, all pass); a trial merge of main; its app run live in the browser pane
against a background-free core on a backup copy of Kenil's world (Home, a project page, the
table, Intelligence, Settings, the panel: every call hit a route main serves); three independent
code reviews (the table views; the companion, appearance and UI kit; the shell, Intelligence,
panel and docs); the copying claim verified by hand against `Zazoo-main`.

## Verdict

Not mergeable as one change, and not only because of the conflicts. It is three pull requests
of very different value in one:

1. **The table views and the UI kit** (`dataviews/`, `ui/`, ~4,500 lines) are good work and
   should come in, rebased on main, with the fixes in §2. Every API call they make exists on
   main's core and was exercised live.
2. **The companion, appearance and the name "Zazoo"** should not come in. The companion is
   copied from Zazoo-main (three files byte-for-byte, all 17 artwork files identical by
   checksum, the avatar component 88% identical, the colour tokens and fonts Bridge's), which
   the standing rule forbids; the product is renamed in 147 places; and the appearance and
   avatar settings add about eighteen controls where the rule is no knobs and the look stays.
3. **The shell, the panel, Intelligence's item pages, the graph and ⌘K** were built on a main
   that no longer exists: main's 3 October work (conversations with routing, People &
   Companies, skills as one table) collides with all of it, the PR drops Activity and People
   from the rail, and the Skills tab crashes against main's current API. Redo on main; keep
   the ideas worth keeping (⌘K, item pages, AboutYou).

The two documents ask the core for about sixty routes, most "to be ported from
`feat/bridge-parity`": multi-provider models with API keys, a per-chat model and access mode,
onboarding questions, person-authored skills, hand-edited reader and automation text. That is a
different product from the one the design describes, and several items contradict rules decided
with Kenil (no knobs, mechanisms not prompts, Alpha's know-how never patched by hand, nothing
per use case). Whether to go that way is Kenil's decision, not a backend request.

## 1. What is good

- The table views: eleven views where main had five; compare-and-swap edits kept on every
  write; the file field, Open/Reveal, export and the module drop zone all ported; rows
  reachable by keyboard; windowing for tables over 100 rows; a record page with a back stack;
  tests for the things that matter (click opens, double-click edits, revision sent, file field
  not editable as text).
- The UI kit: one `Button`, `IconButton`, `Badge`, `Input`, `Segmented`, `Tabs` with arrow
  keys, `IconButton` requiring a label. A clean step from raw `.btn/.pill` classes.
- Self-hosted fonts (the app no longer needs the network for its type: a real fix for a known
  gap).
- Discipline: no `fetch` outside `client.ts`; nothing under `core/`, `connectors/` or the host;
  a layout check at two window sizes; `ponytail:` marks on every place that waits for the core.

## 2. The table views: merge after these fixes

High:
- **Assumed values lost their mark.** Main drew `?` on a number that rests on an assumption;
  the new cells draw `≈` for estimates only and move "assumed" into a hover tooltip. A guess
  then looks like a stated number, which the trust rule (design §7) forbids. Bring the mark
  back.
- **Old saved lists vanish on upgrade** (`alpha.page.<t>.lists` is not migrated to
  `alpha.dv.<t>.lists`). Migrate them, and then move saved lists into the core: they are
  world data (Alpha should see and make them), not a per-viewer convenience.

Medium:
- The row menu's Delete removes without asking (the drawer and the bulk path ask).
- Bulk set and delete are one request per row in sequence; a refusal mid-way leaves half done
  with a generic error.
- Stale closures in the list autosave (the lint rule is switched off there) and in
  `useSavedViews`; two quick changes lose one.
- A linked record from another table gets this table's file context, so "Add file" posts the
  wrong table and orphans the document.

Low: the provenance count includes gone rows; the tooltip still says "click to correct" after
the click became "open"; `load()` has no stale-response guard; relation fetch errors show raw
ids; the ModulePage checks for "there is no project" where the core says "module"; the map's
108 KB topology is in the main bundle; SVG nodes with `role="button"` inside `role="img"`;
board → table keeps the grouping. Tests to add: provenance marks, deletes and their
confirmations, a refused edit, export, bulk, the migration.

## 3. The companion, appearance and the name: decline

Verified by hand: `director.ts`, `parts.ts` and `species.ts` are identical to
`Zazoo-main/platform/apps/web/src/app/avatar/zazoo/`; all 17 panda `.webp` files match by
MD5; `ZazooAvatar.tsx` differs in 166 of 1,367 lines, about 60 of them real additions (trailing
ears, a contact shadow, studio light, eye highlights); `tokens.css` is "ported from Bridge's
palette" with Bridge's hex values and fonts; `panel.tsx` is "ported from Bridge's
PanelControl"; `Character.tsx` says "Bridge's Zazoo companion rig, ported wholesale"; the
30-animal table is Bridge's data; "Bridge" appears 22 times in the source. The rule for this
repository (`../../CLAUDE.md` at the folder above, since 1 Oct) is that Zazoo-main is a
philosophy reference only and never copied. This cannot come in as it stands; a richer
companion needs either rights from the other product's owner or a rig and artwork made from
scratch.

The name: "Zazoo" replaces "Alpha" or "Assistant" in 27 person-facing strings and 147 places in
all, including "Reset to Zazoo" in Settings, and `ui-rules.md` makes it a rule. The product's
name is Kenil's decision and the standing note is not to name it Zazoo.

The settings: Appearance gains Theme (with Ambient; the default flips from Match Mac to Light),
companion colours, ten accents, seven fonts, text size, density, corners, contrast, motion and
rows per page; Avatar gains the animal (30), fur, suit, tie, shirt, neckwear and glasses. All in
`localStorage`, none in the core. The design says the look stays as it is (1 Oct) and the rule
is behaviour, not knobs. Theme and Motion are the two a person reasonably meets; the rest is
Bridge's product.

Also: the companion's animation loop runs every frame for as long as the window exists, with
blur filters and a blend layer, never pausing when idle or hidden. On an always-on-top window
that is steady CPU and battery for a panda that is blinking.

## 4. The shell, panel, Intelligence pages, graph and ⌘K: redo on main

- **Intelligence › Skills crashes against main.** Main's `/api/intelligence` returns `skills`
  as the one know-how table (kind read / act / run) and the connectors as `hands`; the PR reads
  `s.title` and `s.tools.map` on skills, so the tab and every `#/intelligence/skills/<name>`
  address hit the crash screen. `hands` is never read; act and run skills never appear.
- **The panel is built on the stream main replaced.** Main's panel has the conversation strip,
  per-conversation sending, Done, a `routing` turn state and a routing question with choices,
  and `id` can be null. The PR's panel waits only on `running`, never sends `conversation`
  (so main would route every sentence through the judge), has no UI for a routing question,
  and keeps which thread is open per place in `localStorage` (`alpha.sessions`), which the
  core now holds. Twelve conflict hunks in that one file.
- **The rail** is Home · projects · New · Intelligence · Settings: Activity moved into a bell,
  and People & Companies (main, 3 Oct) is absent; the PR's rail test asserts the opposite of
  main's. A person has two pages (`#/intelligence/brain/<id>` and main's), only main's shows
  the wiki page.
- **Hash routing** is hand-rolled (`pushState`/`popstate` in App and Rail); main has none.
  Having addresses is a fine idea and should be decided once, on main.
- **Second brain** (the graph, the default Intelligence tab): a synchronous all-pairs force
  layout in an effect, measured at 0.85 s for 500 nodes, 4.0 s for 1,100 and 8.3 s for 1,600,
  rerun every 20 s because the home poll hands it a new modules array, with no hidden-window
  check; `/api/people` stops at 500 per kind so a 1,551-connection world is cut without saying
  so; the facts it links are only the person's, so people never get an edge. Not in the design.
  Drop it, or redesign it against the entities and the wiki with a layout worker.
- **Item pages** (`IntelItem`): no script or steps are editable (good), but a reader's URL and
  description, an automation's full instructions, a connection's target and the built-in
  hands' names are "drafted to Zazoo" as replacement text that overwrites whatever the person
  was typing, and leaving a field saves it. Reader and automation text is Alpha's know-how:
  the page may say "ask Alpha to change this", never prefill a replacement. `skill:` pages
  (Alpha's notes on its skills) become hand-editable through `POST /api/notes`, and the save
  drops the summary.
- **⌘K** searches six fixed pages and project names, calls no route, and has no People entry;
  main serves `/api/search`. Wire it there; the design's "search everything" is close.
- **`projectIcons.ts`** picks an icon from words like food, job and workout: per use case.
- Keep as is: AboutYou, ActionCard, the Automations list (fix the swallowed switch error).

## 5. The two documents

`backend-requests.md` is a list of about sixty routes and host commands, most already written
on `feat/bridge-parity`. Against the rules decided here: hand-patched readers and automation
text (`PATCH /api/readers`, `PATCH /api/automations {procedure}`), person-authored skills,
overrides on the built-in hands, model pickers and a "Thinking" setting, per-chat access modes
("Approve for me", "Full access"), attachment caps, saved views in `localStorage`. Against
main as it is: `/api/threads` (main has conversations), `/api/pending` (main has actions). The
document should not live in the repository as a request list; the decisions it implies belong
in the design's §11, each as a question for Kenil.

`ui-rules.md` has good rules (terse copy with explanations in a tip; five type sizes; a
no-overflow check at two sizes; reuse the kit; no glyph icons) next to ones that contradict
this repository (the assistant is Zazoo; a module is a "project"; hash addresses; a rail
without People & Companies). Fold the good ones into `CONTRIBUTING.md` §3.8 and drop the rest.
`docs/development/` is not a place the docs structure has (STATE, log, design).

## 6. What I would ask Vikas for

1. **Split it.** Three pull requests, each under about 2,000 lines, rebased on today's main:
   (a) the UI kit; (b) the table views with the §2 fixes; (c) ⌘K on `/api/search` plus the
   item pages made read-only for know-how. Each with its tests and, for (b) and (c), one
   journey in `journeys/` that a person's sentence exercises.
2. **No Zazoo code, art or name.** The blob stays until a companion of our own is made.
3. **No settings beyond Theme and Motion** unless Kenil decides otherwise.
4. **Read `CONTRIBUTING.md`** (written today): the layout, the client-only rule, world data in
   the core, mechanisms not prompts, measured claims.
5. **Backend asks become design questions**, one line each, for Kenil to decide in §11; the
   bridge-parity branch is not a source to port from until those are decided.
