# Agents, schedule first (9 October 2026)

Item 2 of "lets do 1 and 2": the shell around each recurring process (Q33), built over the
automations that exist, never a second scheduler. An automation is now an agent's process: it
has a goal, a page, runs with verdicts judged by code, a repair policy, and its failures reach
the person. Triggers by event, escalation as a question and the digest are left (the design's
§6 box says so).

**A row per run, with a verdict by code** (`world/runs.py`, the `runs` table, `automation.run`,
`pipeline.PipelineResult`). Every run starts a row and ends it with a verdict: *succeeded* when
everything the run set out to read was read and every reader stayed healthy; *partial* when
something was read and something was not (a source unreachable, a reader broken and not
repaired, a sign-in needed), with why; *failed* when nothing was read of what there was to
read, or the run itself broke (the model could not finish, Alpha's tools didn't answer). The
verdict is never the model's opinion: a pipeline's comes from what its steps read, a
procedure's from whether the turn finished with its tools answering. The row also keeps the
run's line, the model's own time in it and the repairs made, so the person can see which runs
cost a model turn and which cost none. A failed run writes a `failed` line in the journal,
which the companion already carries (9 Oct, reliability).

**A goal and a page** (`automations.goal`, the wiki scope `agent:<id>`, `automation_create` and
`automation_update` with `goal=` and `guidelines=`). The goal is the person's words for what the
agent is for. The page is Markdown Alpha writes when it builds the automation (the build rules
ask for it: what it is for, what a good run looks like, what to do when a source needs a sign-in
or stops reading, what to tell) and the person edits in the window. The model reads the page
whenever it steps into a run: in front of a procedure's prompt, and in a repair's prompt. The
page sits in its module's area on the map.

**The repair policy, in code** (`pipeline.REPAIRS_PER_RUN`). A reader that comes back broken is
repaired and rerun, at most twice in one run; then the run says "couldn't be repaired" and its
verdict is partial or failed. That is a judgement of failure, not a cap on work: the next run
tries afresh. (Before, one repair, then the step was given up.)

**The window** (Intelligence › Agents, the agent's page, the module's Agents section). The list
shows each agent's goal and the last run's verdict with why. The agent's page shows its goal, the
last verdict, "Its page" (editable in place; "Ask Alpha to write it" when there is none), what a
run succeeds on in words, and every run from the table with its verdict, line, model time and
repairs; the journal's lines of that run under it.

**Tools.** `automations_list` says each one's last verdict and why; `automation_create` and
`automation_update` take `goal` and `guidelines` (still 72 tools: no new tool).
