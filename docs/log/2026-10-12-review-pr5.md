## Verdict

Not mergeable as it stands, and the gap is wider than the nine conflicts. The branch is a
large, careful piece of window work (the data view after Notion's database, a kit with real
tests, the brain egg over 2,812 records, plain words for failures) built on a main that no
longer exists: it predates modules as workflows (Q39), the per-field provenance and Try again
of 11 Oct, the questions form, and the removal of plans and the research pass (Q40). It also
takes product decisions that are Kenil's (what the person is shown, what is called what, what
the core must become) under the name "the owner", who in every log entry is Vikas.

Three things before anything else:

1. **Merge today's main into the branch and port what main added since 10 Oct** — the
   window otherwise loses it: per-field sources, dates and problems on a record
   (`_provenance.fields`), "Try again" and the part buttons, readonly tables, the workflow
   card and its yes, questions asked together as one form; and it still calls
   `/api/plans/*` and `/api/research/*`, routes main removed on 12 Oct. Seen live: the record
   page says "the core keeps provenance for the whole record, not value by value", which is
   false since 11 Oct, and shows "Source: Unknown" for a score the core knows came from the
   Texas Comptroller.
2. **Separate the product decisions from the window work** and bring them to Kenil as
   questions (below). The branch reverses "keep it similar to current alpha" (Kenil, 1 Oct),
   keeps the Assistant page out of the rail (against Q35), renames "module" to "project"
   through the design document's history (five of Kenil's own decision rows rewritten),
   renumbers its decisions Q39–Q42 over main's Q39–Q40, and asks the core for workspaces with
   sign-out, a shipped Task manager with named agents and WIP limits, a depth picker tied to
   model tiers, hand-edited skill instructions and per-project rules in free text.
3. **Remove what the rules refuse** before merge: the Governance "Allowed / Denied" card (a
   permission the runtime never reads, shown as if it bound Alpha), the composer's Depth
   knob, the data view's "Load limit", and the "Add new…" row every dropdown carries.

## 2. Defects (verified unless marked)

High:
- **Provenance per value, Try again and readonly lost** (`modules/RecordPage.tsx`,
  `modules/views/RecordPanel.tsx`, `modules/DataPage.tsx`, `core/client.ts`): no
  `readonly`, no `fields` on provenance, no `parts()`/`runPart()`; `tableSource` never
  consults `table.readonly`, so a workflow's table is editable and deletable from the
  window. Seen live on the scorecard.
- **Multi-column paste races itself** (`views/TableView.tsx:258-271`): one `edit` per cell
  with the same revision, so a pasted two-column line half-applies and the second write is
  refused by the core's compare-and-swap. Group the cells by row.
- **Governance "Allowed / Denied"** (`modules/ModuleSections.tsx:323-350`, on every project
  and on Network): titled "What Alpha may do here", stored in a `governance_rules`
  preference the core never reads; the real, enforced permissions sit one card away in
  Settings. Prompt, not mechanism; a trust problem.
- **"Add new…" on every dropdown** (`ui/Dropdown.tsx:264-267, 137-158`): with no `onAdd` it
  opens a dialog that sends `Add a new option to "<label>": …` to Alpha, on Conversations,
  Depth, Rows per page, Move to, Condition, And/Or, Row height, Load limit, Chart type…
- **The branch's assistant is behind main's**: still renders the plan card and calls
  `approvePlan/declinePlan/stopResearch`; no `AskGroup`, `WorkflowCard`, `Questions`.
- **One preference key per map hits the core's 20,000-character cap**
  (`core/preferences.ts:14-33`; `world/preferences.py:33`): `view_settings` holds every
  list's filters, sorts, groups and colours; `workspace_logo` is a 128-px PNG data URL
  (25–60k characters for a photo), so "Change logo…" fails on most images (by arithmetic,
  not run).

Medium:
- **Cancel on a record** (`modules/RecordPage.tsx:73, 402-405, 453`): "made in this visit"
  is "since the window launched", and Cancel's only effect is delete, offered after Save too.
- **Window-only renames** (`shell/Rail.tsx:251-257`, `module_names`): the person sees a name
  the core, the assistant and exports do not know; and the window's `network` pseudo-id is
  written into `module_order`, `hidden_modules`, `module_names`.
- **Marks** (`views/cells.tsx:126-130`, `views/engine.ts:103-111`): Estimated/Assumed chips
  are visible (good, the PR #3 regression is not repeated) but only on number columns, so a
  row-level assumption on a text table shows on no cell; the source is hover-only; a row
  both estimated and assumed is counted once.
- **Record history** (`record/RecordHistory.tsx:9`, `RecordPage.tsx:149`): real, from the
  journal, but through `activity(limit=500)` on the module; truncates silently on a busy
  module. Needs a per-record journal query in the core.
- **Agents** (`shell/agents.ts:21-40`): "Alpha" plus one "<project> runner" synthesised per
  module that has automations ("Deal Tracker runner", "Nutrition runner" seen live). Q33 says
  an agent is one automation with a goal and a page (`agent:<id>`); the window invents a
  second kind the core has no record of.
- **Depth** (`assistant/Composer.tsx:21-35, 138`; `shell/Settings.tsx:422`): "Quick overview
  / Deep thinking", Deep disabled, with a stored default. A model-tier knob the core does not
  take, shipped disabled; PR #3's review already refused it.
- **Layout check** (`desktop/scripts/layout-check.mjs`): launches Edge, Chrome or Chromium,
  never WebKit, which the app is; duplicates `just check-desktop` (`journeys/desktop.py`)
  with its own sizes and report folder; `launch()` sits outside the `try`, so a missing
  browser leaks the spawned core and the scratch home; with `ALPHA_WINDOW_URL` it saves a
  view in whatever world that window is on.
- **Claims**: "no raw px left in app.css" — 277 lines carry `px` outside the token block
  (`.iconbtn` 42px, `.page` 1480px, `.more` 300px…; the source-rule test checks only padding,
  margin, gap, inset, radius and font-size); the scale comment at `app.css:36-38` ("md 12,
  base 13") contradicts the values (md 14, base 16); "core 247 tests" is 226 on today's main.

Low:
- WebKit, unverified in the app: trackpad pinch on the egg expects a ctrl-wheel (WebKit sends
  `gesturechange`), `foreignObject` avatars inside a scaled, clipped `<g>`, `onDragLeave`
  through `relatedTarget` (null in WebKit: a flicker), `scrollbar-width: none` without the
  `::-webkit-scrollbar` fallback at one place, `navigator.clipboard.readText()` often absent
  in WKWebView (handled with a message). The drag-to-nest fix is proven in jsdom only.
- Dropdown roles: two comboboxes, no `aria-expanded`, `aria-activedescendant` can name the
  "Add new…" button; Properties reorder is drag-only; the first-run folder instruction hides
  in a hover tip.
- Three "ponytail" markers (window lists read-modify-write one preference; the CSV grid draws
  every row; history's limit); `fieldLabel` and `isEmpty` defined twice; four local-ISO-day
  helpers; `DataPage.tsx:364-376` re-registers ⌘Z every render; `singular("Series")` →
  "Sery"; `duplicate` copies file and relation ids.
- Settings pages that exist only to say "Nothing configured yet": Notifications, Builder
  rules, Removed projects; "Manage Workspace", "Sign out", "Organizations: not linked yet"
  disabled.

**The branch's own layout check**, run here on a copy of Kenil's world (Chrome, 272 states at
