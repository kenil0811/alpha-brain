## P6: documents with positions

- **Reading keeps where things are** (`connectors/files.py`, `read_document`).
  - A PDF is read page by page: `[page 3]` before each page's text.
  - A sheet is read cell by cell, the workbook twice (values, and formulas):
    `12: A=Total revenue | B=48200 (=SUM(B2:B11))`. A formula Excel never worked out shows as a
    formula with no value.
  - `.xls` is read through `xlrd` (a new dependency, question 2).
  - A CSV is a sheet of one: its cells and the import work on it, and its text is as it was.
- **The document's structure is kept** (`documents.structure`): its pages, or each sheet's name,
  rows and columns.
- **One file, one document** (`documents.hash`, the bytes' sha256).
  - Taking bytes that are already kept returns that document, marked as already kept.
  - A file an agent's run fetched that is already kept shows "You have this already" on its
    staged card, with Keep both (question 3).
  - A connected folder's own files never count: they are read where they are.
- **A turn reads only the part it needs.** `document_read` and `world_file read` take `page`, or
  `sheet` with `cells` ("B2:F40"). Each is read again from the kept file. A sheet or page that
  isn't there is refused in plain words ("has no sheet 'Profit'; its sheets are P&L, Notes").
- **A sheet's rows go into a table by code** (`world_file` action `import`, `document_import`).
  - The columns are mapped to the table's fields by their headers, or by `columns`.
  - Code types the rows, never the model. A row with no value in the mapped columns is left
    out, and rows that don't fit are counted.
  - `key` updates on a field.
  - In an agent's run, rows for a staged table wait on its card.
  - Each value's source is its cell (P5).

## P5: each value with its source

- **A value's own source** is kept in `provenance.fields[field]` (`runtime/value_sources.py`).
  - It holds a kind: document, url, stated, formula, estimated or words.
  - It holds the words the person and the model read ("RestoPros P&L Sept 2025.xlsx · P&L!B2",
    "Bank statement Sept 2025.pdf · page 2", "worked out: revenue / months with revenue =
    48200, months = 3"), the position, and when.
- **Given per field.** `world_write` and `world_change` take `sources` ({field: source}), and a
  row may carry its own as `_sources`. A field without one takes the row's source, as before.
  A keyed write now keeps the row's source too; it used to keep none.
- **Code checks a source, never the words.**
  - The document must be kept. Its page must exist. The sheet and cell must be inside the
    sheet.
  - A many-page PDF needs a page, and a formula needs its inputs.
  - A source that fails is refused in plain words, and nothing is written.
- **Compared with what the kept file holds there.** A value from a cell or a page is compared
  with the cell (or the page's text), read again from the file by code.
  - The field carries the mark: ✓, or ≠ with what the cell holds.
  - The write's result says when a value differs, so the model corrects it.
  - Columbo leaves alone what code already read from its place, and rows an import copied.
- **Kept until the value changes** (`collections.carry_fields`). An update keeps the other
  values' sources. Before, an update by Alpha replaced the provenance and lost every field's,
  the person's edits too.
- **The person's change is theirs.** An edit in the window, or a value changed on a staged card,
  is "you" for that field. The other values keep their sources.
- **Seen in the window.**
  - A table cell's hover names its value's own source.
  - A record's Details show it beside the value, with its date and mark.
  - Clicking a document source opens the place in Alpha's own window, read again from the kept
    file: a sheet's cell among its neighbours, highlighted, with its formula; or a PDF's page
    with the value's line marked. The Mac's own app is one click away. A web address opens.
  - "Around it" and `world_query`'s rows carry the same words, so a run sees them too.

## P7: agents woken by events

- **A custom agent's on: lines** (`runtime/agents/events.py`):
  - `{"rows_added": table}`;
  - `{"rows_changed": table, "fields": [...]}`;
  - `{"document_filed": module}`;
  - `{"card_decided": "mine"}`;
  - `{"before_event": minutes, "matching": words}`.

  They are set by `agent_keep` / `agent_create` / `agent_update` (`on`), and are checked
  (the table, its fields, the module). They are kept in the agents table's `events` column,
  which had waited unused since 15 Oct. In the agent's file they are `wakes_on:`, because YAML
  reads a bare `on` as true. The journey's seed met the same thing: its first run woke nothing
  (`docs/journeys/2026-10-19-1527.md`).
- **The look is code, from the store, by data.**
  - On every tick and after every turn, the custom kind's look reads past the agent's marks
    (`agents.wake_marks`):
    - rows added, by their place in `records`;
    - rows changed, by the old values every change keeps in `record_versions`, compared with
      the row now, and narrowed to the fields named;
    - documents filed in the module;
    - its decided cards no run has heard of yet (an Always is not a decision now);
    - the calendar between now and the lead time.
  - What matched goes in front of one run ("Since your last run: 1 row(s) added to Deals:
    Midwest HVAC"), and the run's first line says what woke it. The marks move once the run is
    over.
  - New lines look from the moment they are set. What came before them is not their business.
- **No loops.** What the agent's own runs wrote never wakes it: a row carries the agent that
  wrote it, or the turn in the agent's own thread. A pipeline's reader now keeps its agent on
  the rows too: a review before the build found they carried neither, so a steps agent on its
  own table would have woken itself. Each agent runs once per tick.
- **The words**: `when` reads "every day at 08:00 …; when a row is added to Deals". The words
  are worked out from the store, so an edited file reads right.
- **Removal.** A line naming a table or module that was removed says so on the agent's page
  ("(its table was removed, so it never wakes it)") and never fires. The lines go with the agent.
- An agent with steps may now run on events instead of a schedule.
