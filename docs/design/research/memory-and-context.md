# Memory and context layer — evidence survey (subagent, 2026-09-30)

[V] verified from primary source; [S] secondary; [I] inference.

## 1. Systems (condensed)
- Letta/MemGPT: editable in-context memory blocks + archival (vector) + recall; Mar 2026 moving to git-backed MemFS files and client-side reflection subagents; sleep-time agent rewrites blocks in idle time. Apache-2.0. LoCoMo ~83% [S].
- Mem0: LLM-extracted facts in vector store (+ optional graph); v3 (2026) single-pass ADD-only → contradictions accumulate (issue #4956); MemDelta: −1.2pp vs plain RAG at ~50× cost; Zep re-run ~68% vs full-context ~73%.
- Zep/Graphiti: temporal KG: episode nodes (verbatim) → entity nodes + fact edges with t_valid/t_invalid/t_created/t_expired; contradiction sets t_invalid; entity resolution by embedding+FTS then LLM merge; needs LLM + embedder + Neo4j/FalkorDB. Self-reported LongMemEval +18.5%; LoCoMo disputed both ways (58.44% vs 75.14%).
- Hindsight: four networks (world facts, experiences, observations, mental models); Postgres+pgvector; 4 strategies fused by RRF; self-reported 91.4% LongMemEval; no independent replication.
- LangMem: semantic/episodic/procedural in LangGraph store. Cognee: relational + vector + graph (Kuzu); runs without API keys via GLiNER. Honcho: per-peer representation, dialectic endpoint; AGPL. Supermemory: temporal vector-graph + "dreaming"; MIT. Khoj: chunk embeddings; AGPL; cloud sunset 2026.
- Basic Memory: Markdown notes with typed [observation] lines and [[relation]] wikilinks; SQLite FTS; embeddings optional off by default; AGPL.
- OpenClaw: USER.md, MEMORY.md (bounded budget), daily memory/YYYY-MM-DD.md; SQLite hybrid index; dreaming merges dated notes into MEMORY.md; flush before compaction; embeddings optional.
- Claude Code auto memory: MEMORY.md index (first 200 lines/25 KB loaded) + topic files on demand; 4 types; Is-Grep study: grep 76.7% vs vector 75.0% inline.
- Anthropic memory tool (memory_20250818): client-side /memories files; view/create/str_replace/insert/delete/rename.
- Claude.ai memory: topic entries saved live; per-Project memory + summary; chat search is a separate RAG tool.
- ChatGPT "Dreaming" (2026-06-04): background rewrite of an editable profile summary; time-sensitive entries revised; OpenAI eval 41.5→82.8% recall [S].
- Microsoft Recall: snapshots + OCR + vectors in VBS enclave; TotalRecall bypass again Mar 2026 [S].
- Apple personal context (WWDC26): apps donate entities via entity schemas to the on-device Spotlight semantic index; SpotlightSearchTool lets the on-device model run semantic + structured queries as a tool; Swift only.
- Karpathy "LLM Wiki" (gist 2026-04-04): raw sources (immutable) → LLM-owned Markdown wiki (entity/concept pages, index) → schema file; ingest/query/lint; index suffices at ~100 sources.
- Research: Generative Agents (memory stream scored recency × importance × relevance; reflection when importance sum crosses threshold); A-MEM (Zettelkasten notes; no independent replication); HippoRAG 2 (passages + PPR over entity graph).

## 2. Strongest evidence
1. Keep verbatim text; extraction is lossy: verbatim chunks beat LLM-extracted artefacts by 15.9 pts LoCoMo, 22.0 pts LongMemEval-S; "adding artifacts alongside chunks preserves accuracy; substituting them forfeits the gap" (arXiv 2601.00821 v4). LongMemEval: compressing sessions into facts hurts except multi-session reasoning (2410.10813). MemPalace's 96.6% came from verbatim storage + default embeddings (2604.21284).
2. Mutable facts need update-on-write, not similarity retrieval: MERIT (2609.05441, 23,440 episodes): on updated facts embedding retrieval 0.30–0.95 (unstable), structured fact store 0.75–1.00, LLM summary 0.80–1.00, full replay 0.95–1.00; hybrid worse than fact store alone; generic LLM extraction +0.20 "stale harm" vs pattern-based. Mem0 #4956: "I work at A" and "I now work at B" both persist. Schema-grounded extraction (object → field → value with validation) 97.1 F1 vs 80–87 (2604.27906, self-reported).
3. Model-driven lexical search competitive with vectors; harness matters more than retriever: "Is Grep All You Need?" (2605.15184): grep beat vector on every harness with inline results (Claude Code 76.7 vs 75.0) but reversed when results delivered as files. Keyword-search agents 98–99% of vector-RAG (2602.23368). LongMemEval-V2: coding agent filing trajectories 72.5% vs RAG 48.5% (2605.12493). Boris Cherny: agentic search "works better… simpler… no staleness/privacy issues". Anthropic guide: just-in-time retrieval by lightweight identifiers; hybrid up-front + on-demand for less dynamic data (2025-09-29). Counter: AgentMemBench (2608.00009) dense KV retrieval only strategy scaling on LoCoMo long horizons, but didn't test BM25/grep.
4. Graphs pay off only for multi-hop and synthesis: GraphRAG-Bench (2506.05690): vanilla RAG ≥ GraphRAG on facts; HippoRAG 2 wins complex reasoning (53.4 vs 42.9) and summarisation (64.1 vs 51.3). RAPTOR/GraphRAG/LightRAG underperform standard RAG outside their niche.
5. Benchmarks fragile: MemDelta (2606.29914): embedding model swap ±6.2 pp; verbatim RAG matched full-context; "agent self-memory" 42% vs basic retrieval 47%. Tenure flips rankings (2607.21962): budgeted curated-map memory 96% at 3 weeks → 72% at 9 weeks as evicted content lost; provenance-typed graph rose to 90%; layered design led at both.
6. Recall is not use: MERIT agents acted on a correctly retrieved value only 55%; "Know It, Act on It" (2607.29433): 16 systems pass recall, fail behavioural tests; StreamMemBench (2606.14571); TANGLE (2608.13921): extraction destroys conflicts; best policy preserves alternatives and asks.
7. Where the LLM sits in the write path decides forgetting: ForgetEval (2606.15903): deterministic primitives suffice for lexical/temporal supersession but fail canonicalisation; LLM at inscribe-time or mutation-time hook reaches 91.7–93.2%.
8. Cost geometry: long-context more accurate; memory wins on cost after ~10 turns at 100k (2603.04814). Mem0 DolphinBench: memory +~5 pp over harness memory at higher cost/latency [S vendor].

## 3. Embeddings on Apple Silicon; needed?
sqlite-vec (v0.1.10-alpha, brute-force KNN, thousands–hundreds of thousands of vectors; binary quantisation). MLX embedders (nomic-embed-text-v2 137M ~14,200 passages/s on M5 Max [S]); sentence-transformers mps/ONNX. Apple NLContextualEmbedding 512-d, ≤256 tokens, via pyobjc; quality unbenchmarked; Apple's semantic index Swift-only. FTS5 milliseconds at millions of rows; trigram tokenizer for substrings. Conclusion [I]: not required at launch; design so an embedding column is one more RRF signal later; chunk-ID scheme hash(path:lines:content:model_version) for upgrades.

## 4. Representing a person's world (what the better systems share)
(a) verbatim episode layer with provenance (Graphiti episodes, Hindsight experiences, append-only typed event logs with deterministic projections — 2606.12329/2606.23752); (b) entities resolved first by hard keys then by embedding+FTS candidates + LLM merge; PKG survey open problems: population, entity linking, temporal handling, privacy (2304.09572); (c) facts with bi-temporal validity (valid_at/invalid_at world time; created/expired system time) — supersede, don't delete; (d) typed atoms separating raw evidence, retrieval cues, claims (MemIR 2605.25869); (e) standing instructions/behavioural specs kept apart from facts — compact behavioural spec beat Mem0/Letta/Supermemory/Zep on interpretation at ~25× less context but hurt recall (2605.28969); (f) small always-loaded index + everything else on demand; (g) idle-time consolidation rather than per-turn rewriting.

## 5. Three candidate architectures
A. Files-as-memory + FTS5, model-driven search: verbatim in SQLite+FTS5; curated Markdown notes (profile, instructions, topic pages); per-topic tables; bounded index note per turn; model greps/FTS/SQLs; idle lint/dream. Failure: curated notes decay with tenure (96→72%); vocabulary mismatch; cross-source links re-derived each time; index bloat.
B. Typed world model: A + entity(id, type, canonical, aliases, keys{email,url,phone}); fact(subject, predicate, object, valid_from, valid_to, recorded_at, superseded_by, source_id, confidence); event(ts, kind, entity_ids, source_id); instruction(scope, text, since); verbatim rows are source of truth, derived tables regenerable. Context: deterministic pre-pack (0 model calls): profile + instructions + entity cards mentioned/linked + last-N timeline + FTS hits; tools for follow-up SQL/FTS. Consolidation: supersession at write for hard-key facts; batched LLM extraction of soft facts; nightly reflection writes entity summaries with provenance. Entity linking deterministic on hard keys (email, LinkedIn URL, attendee) → 0 calls; soft matches proposed to the person. Failure: extraction cost/errors (stale harm), over-merging, must not let facts replace text, conflict policy (TANGLE). Model calls: 1 per turn + 1 per tool step; ingest 0 calls for structured sources, ~1 per 10–20 items for soft facts in background; reflection capped nightly.
C. B + local embedding signal (sqlite-vec, RRF).

## 6. Ranked recommendation
1. B — build this: matches verbatim retention, update-on-write for mutable facts, model-driven lexical/structured retrieval with a deterministic pre-pack keeping most turns to one call. Signature behaviour (recruiter email → application → LinkedIn contact) is a two-hop join on an entity registry with hard keys — relational, no graph DB. Keep Graphiti's four timestamps + supersession; MemIR's evidence vs claim separation.
2. A as the first milestone inside B: notes/index/lint loop is cheap and proven; ship entity registry + fact table before months of history accumulate.
3. C only after measured need: personal DolphinBench-style eval; sqlite-vec + small MLX/ONNX embedder only if FTS+SQL recall is the bottleneck.
Open questions: source of truth (immutable verbatim log; reconcile clean removal via tombstones + re-projection); entity resolution policy (auto-merge only hard keys; who confirms soft merges; undo); conflict policy (newest-wins vs preserve-and-ask; per fact type); per-turn budget (always-loaded cap; tool steps at ~8 s); extraction budget (which sources get LLM extraction; batch size; nightly cap); proactivity triggers as deterministic rules over event/entity tables, model only phrases/judges; the "act on retrieved value" check (MERIT 55%); evaluation: tenure-aware personal eval before any vector/graph addition.
