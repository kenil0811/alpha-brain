# Continuity/proactivity (A) and "when to make it standing" (B) — research report (subagent, 2026-09-30)

[V] verified; [I] inference/design proposal.

## 1. Proactive agents as they exist now
- OpenClaw (ex-Clawdbot/Moltbot) [V]: heartbeat every 30 min (1 h on Anthropic OAuth) as a main-session model turn; cron/interval/one-shot automations in isolated sessions; webhooks; lifecycle hooks; "standing intents" (event-conditioned, keyword-matched, no model call; defaults 24 h cooldown / 3 fires / 90-day expiry). Heartbeat prompt "If nothing needs attention, reply NO_REPLY"; heartbeat_respond notify:true/false; per-job "monitor scratch" checklist; activeHours quiet window. Skills gate tools; "standing orders" in AGENTS.md: scope, triggers, approval gates, escalation. Memory: MEMORY.md (curated), daily memory/YYYY-MM-DD.md, USER.md, hybrid SQLite search; silent memory-flush before compaction; "dreaming" promotes daily notes to MEMORY.md by thresholded scoring. Complaints: issue #21597 (Feb 2026) heartbeat-only session consumed 47.6M tokens/779 tool calls in a day, 117M in a prior incident, closed "not planned"; #64293 heartbeat 2M+ tokens/day idle; heartbeat resends ~100K context per run unless isolatedSession (2–5K). "Cost tracks context size, not visible activity."
- ChatGPT Pulse [V]: nightly async job; 5–10 cards from memory, chat history, thumbs, optional Gmail/Calendar; cards expire after a day; "that's it for today"; off by default; read-only; Pro-only preview Sept 2025; deliberately anti-scroll.
- OpenAI "dots" (29 Sept 2026) [V]: always-on agents with own cloud computer; user assigns goals; idle → proactive read-only research over connected apps; owner-set autonomy; progress updates and questions; "actions that could touch a user's accounts or share information must first clear auto-review"; safety monitor can pause; learns preferences from feedback.
- ChatGPT agent / Operator [V]: user-initiated; confirmation before consequential actions; watch mode on sensitive sites; Operator deprecated 31 Aug 2025; ChatGPT agent removed early Aug 2026 (single source).
- Claude Cowork scheduled tasks / Claude Code Routines (15 May 2026) [V]: hourly/daily/weekly/manual; cron, API call, GitHub webhook; runs saved prompt; approval mode at creation; each run own session; auto-memory (4 types; loads first 200 lines/25 KB; saves what "would be useful in a future conversation"; skips what is derivable). Reliability/quota complaints (InfoQ).
- Microsoft Copilot Autopilot (25 Sept 2026) [V]: name, role, goal; works while you sleep; boundaries set up front; private preview. Microsoft cancelled "Your Day at a Glance" proactive push notifications (26 Aug 2026).
- Windows Recall [V]: snapshots every few seconds; opt-in; Windows Hello every launch; local; sensitive-info filter; 2024 backlash forced opt-in redesign.
- Google Gemini [V]: scheduled actions (Jun 2025); Goal Scheduled Actions beta (Feb 2026) "reviews outputs from the previous instruction and adjusts"; Gemini Spark (19 May 2026): cloud agent, recurring tasks/triggers, Daily Brief steered by thumbs; "ask you first before high-stakes actions like spending money or sending emails"; Ultra-only.
- Apple Siri AI (beta 14 Sept 2026) [V]: user-initiated; opt-in; on-device + PCC; Siri Suggestions learn from app "donations", time, location.
- Limitless / Rewind [V]: Meta acquired 5 Dec 2025; Pendant sales stopped; Rewind capture killed 19 Dec 2025.
- Dot (New Computer) [V]: shut down 5 Oct 2025; 24.5K lifetime iOS downloads.
- Cluely [V]: continuous audio+screen; 5–90 s delays, generic suggestions; 1.7/5 Trustpilot.
- Cora (Every) [V]: every inbound email; twice-daily brief for non-urgent; "never sends emails for you" — drafts only; praised for narrowness.
- Lindy [V]: email/Stripe/CRM/cron/webhook triggers; "Ask for Confirmation" only on actions with side effects; approval via task view + email.
- Zapier Agents [V]: default executes without stopping; approvals written into instructions.
- Relay.app [V]: shut down Sept 2026.
- Manus [V]: Scheduled Tasks 2.0 (18 May 2026); "skip confirmations for trusted workflows".
Pattern [I]: nobody has shipped continuous observation-driven proactivity for consumers and kept it. Survivors: (a) scheduled/goal jobs delivered as a batch (Pulse, Spark, Cowork, Manus); (b) event-triggered agents with side-effect gating (Lindy, dots auto-review, Gemini ask-first); (c) OpenClaw's heartbeat = the cautionary tale.

## 2. Strongest evidence on interruption and proactivity
- Horvitz, Mixed-Initiative UIs (CHI 1999): act autonomously only when EU(action) > EU(inaction) under goal uncertainty; model attention; defer; minimise cost of poor guesses; efficient correction [V].
- Iqbal & Bailey (CHI 2007/08): breakpoints predicted at 69–87%, interruption cost 56–77%; deferring to breakpoints reduced frustration and reaction time [V].
- Proactive Agent (Tsinghua, arXiv 2410.12361): ProactiveBench 6,790 events; best model F1 66.5% with 100% recall but 50.2% false-alarm rate; models "provide as much assistance as possible, instead of necessary assistance" [V].
- "Need Help?" (CHI 2025, arXiv 2410.04596): Suggest preferred by 90%; Persistent Suggest (5 s, 5 suggestions) dropped to 47%; trigger: suppressed while typing, fire after 5 s idle, max 1 per 20 s, immediate on error [V]. "Assistance or Disruption?" (arXiv 2502.18658): 30 s idle threshold growing when ignored + task-boundary signals; 53.3% engaged, 12.1% disruptive, 34.7% ignored [V]. IUI'26 field study (arXiv 2601.10253): 52% acceptance at workflow boundaries vs 38% mid-task; well-timed suggestions took 45 s to interpret vs 101 s reactive [V].
- Proactivity-Gym (arXiv 2609.37267, 29 Sept 2026): 97.8% accepted imperfect sleep-time assistance vs 26.7% for correct-but-intrusive help; trust losses from one misaligned intervention exceeded gains from realignment; best agent 65.1 capability but 51.7% temporal allocation [V]. Letta sleep-time compute (arXiv 2504.13171); ProAct (arXiv 2605.25971): idle-time anticipation cut turns 14.8%, hallucination 28.1% [V].
- Edwards et al. (CUI 2024, arXiv 2405.07528): adaptive proactive agent rated worse than a static one; inconsistency hurt [V]. "1,000 Personas" (arXiv 2602.04000): mistimed behaviour → users disable features; on-device steering from thumbs improved timing [V].
- GUM/Gumbo (arXiv 2505.10831): screen observations → confidence-weighted propositions; suggest only when EU_interrupt > EU_not; token bucket 1/min; N=5, accuracy 0.79 [V]. ProCodeBench (arXiv 2605.05700): 13.6% Pass@1 predicting next intent [V].
- ProAgent (arXiv 2512.06721): tiered on-demand perception → 20.5% fewer false detections [V].
- LangChain ambient agents (Jan 2025): event streams; notify / question / review primitives [V].

## 3. Proposed mechanism for (A) [I]
Four layers, cheaper as you go down:
1. Sensors (no model): connector deltas, schedule ticks, derived-table changes (tracker crossing a target), person-context signals (idle start, app switch, calendar gap, session end, day start/end). Typed events in an append-only log. No screen capture in v1.
2. Triage (rules + small model, ≤ ~2K tokens/event): discard / record (silent memory/table update) / escalate. Standing intents (keyword/structural, no model) run here.
3. Deliberation (full model) only on escalation, isolated run with a compact situation packet (event, relevant standing things, goals/facts, last digest). Never the full conversation. Hard caps: tool calls, wall-clock, no self-scheduling.
4. Sleep-time consolidation (nightly + long idle): memory consolidation, precomputation for predictable needs (tomorrow's meetings, due follow-ups), digest assembly. Most proactivity lives here (97.8% vs 26.7%).
Worth speaking up: expected-utility gate. Each candidate: confidence p, benefit B, false-positive cost, decay horizon. Tiers vs the next scheduled batch: prepare (silent) → digest (morning + end of day, fixed times) → in-workspace card (at a breakpoint) → interrupt (only if horizon shorter than next digest, p high, asymmetric miss cost; deferred to a breakpoint: idle > 30 s, app switch, calendar gap; small per-day token bucket). Fixed digest times + consistent style beat adaptive cleverness. Dismiss/ignore = rejection; per-topic thresholds move; a misfire raises the bar more than a hit lowers it.
Cost bounded without knobs: no model call without an event or scheduled slot (no heartbeat model turn; heartbeat = deterministic health check); tiered models by layer; isolated packet-sized runs; per-run caps; internal daily compute budget that degrades behaviour (batch more, speculate less) instead of alerting; skip a scheduled run when nothing changed.

## 4. Proposed mechanism for (B) [I]
How existing systems make durable artifacts [V]: Voyager (skill only after passing self-verification, ≤4 refinements; embedding index; composition); Reflexion (lessons, not procedures); Agent Workflow Memory (workflows from successful trajectories, +24.6% Mind2Web, +51.1% WebArena); SkillWeaver (propose → synthesise → hone); SCAFFOLD (EMNLP 2026: skills abstracted from multiple successful trajectories; pruned by MDL + behavioural equivalence); ReUseIt (IUI'26: successes and failures with execution guards, 24.2%→70.1%); cautionary arXiv 2606.20363: SKILL.md mined from raw GUI trajectories → negative transfer (44.2% vs 55.8% zero-shot). Claude Code: Claude does not create skills itself; make a skill "when you keep pasting the same instructions… or when a section of CLAUDE.md has grown into a procedure"; /skill-doctor reports context cost + invocation frequency; auto-memory saves only what would be useful later. Anthropic Skills post envisions agents autonomously creating/evaluating skills. OpenClaw: skill_workshop; standing intents/orders. Task mining (UiPath, Process Advisor): record clicks/keystrokes/screens, cluster, rank by repeatability × time; analysts pick; PII masking. Eager (Apple CHI'91): always-on repetition detector reveals its hypothesis by highlighting the anticipated next action. Siri Suggestions: donations of repeated actions. Gmail Nudges: resurface after ~3 days. workflow-use / Stagehand: agent run once → deterministic parametrised workflow (~10× faster, ~90% cheaper), agent fallback, selfHeal. xkcd 1205 + maintenance/obsolescence/error cost.
Signals (cheap, logged per request): 1 explicit ask semantics (recurrence words, targets, scope); 2 repetition (same intent-class count in a window; periodicity); 3 hand cost (agent effort last run; person's effort if observed); 4 substrate (connector exists? deterministic last run?); 5 goals/profile facts (goal-attached asks are standing by default); 6 risk (outbound writes, money, third parties); 7 outcome (verified success, no correction).
Ladder: Level 0 do it (first occurrence, no recurrence language, no goal) — log trajectory. Level 1 candidate (recurrence language OR second occurrence OR goal attachment) — record as a parametrised template with slots; nothing visible. Level 2 standing thing — promote when E[occurrences] × hand cost − (build + maintenance) clearly positive AND ≥1 verified successful run AND ≥2 instances or explicit recurrence ask. Kind by substrate: conversational procedure → Skill; cross-app deterministic steps → Workflow (deterministic replay + agent fallback); ownerless recurring work with triggers → Agent (standing order: scope, trigger, approval gates, escalation); data to persist/view → Module (table + derived page + targets).
Propose vs do: standing ask that only reads → build and show with a one-line note + remove affordance; derived from repetition → propose at a breakpoint or in the digest with evidence; will write outbound → always propose, approval gates set at creation.
Junk avoidance: create only from verified successful runs; abstract not clone (dedupe by behavioural equivalence); provenance + test + triggering description per artifact; usage decay → demote; failing twice → fallback + repair task; rejection suppresses the class for a long cooldown; removal deletes everything related.
